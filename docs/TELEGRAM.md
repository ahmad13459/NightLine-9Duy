# پروکسی تلگرام — چهار روش

همهٔ روش‌ها روی **همان یک پورت TCP** سرو می‌شوند (مالتی‌پلکسر). فعال/غیرفعال کردن هر روش از تب «تلگرام» انجام می‌شود و سرویس بدون ری‌استارت کل پنل، فقط همان بخش را به‌روز می‌کند.

## ۱) MTProto با FakeTLS (پیشنهادی)

- موتور: [mtg](https://github.com/9seconds/mtg) نسخهٔ ۲٫۳ (باینری داخل ایمیج).
- سکرت به‌شکل `ee<۱۶ بایت هگز><هگزِ دامنه>` ساخته می‌شود؛ همان قالب استاندارد تلگرام.
- دامنهٔ FakeTLS باید یک سایت واقعی با TLS 1.3 باشد (`www.cloudflare.com`، `www.microsoft.com`، ...). کلاینت در واقع با همان دامنه TLS می‌بیند.
- لینک‌ها:
  - `tg://proxy?server=<tcpHost>&port=<tcpPort>&secret=<secret>`
  - `https://t.me/proxy?server=...`
- مسیر در مالتی‌پلکسر: ClientHello با SNI برابر دامنهٔ FakeTLS → پورت داخلی mtg.

### آزمایش دستی

```bash
# باید یک دست‌دادن TLS با گواهی دامنهٔ FakeTLS برگردد
openssl s_client -connect <tcpHost>:<tcpPort> -servername www.cloudflare.com </dev/null
```

## ۲) SOCKS5

- پیاده‌سازی داخلی Node ([`src/proxy/socks5.js`](../src/proxy/socks5.js))؛ CONNECT برای IPv4/IPv6/دامنه.
- احراز هویت نام‌کاربری/گذرواژه (RFC 1929) و بدون احراز هویت هر دو پشتیبانی می‌شود؛ در پنل روشن/خاموش کنید.
- لینک: `https://t.me/socks?server=<host>&port=<port>&user=<u>&pass=<p>`
- مسیر در مالتی‌پلکسر: نخستین بایت `0x05`.

```bash
curl -x socks5h://user:pass@<tcpHost>:<tcpPort> https://api.telegram.org
```

## ۳) پراکسی وب / HTTP

- پیاده‌سازی داخلی Node ([`src/proxy/http.js`](../src/proxy/http.js))؛ هم `CONNECT` (HTTPS) و هم forward سادهٔ HTTP.
- احراز هویت Basic روی هدر `Proxy-Authorization`.
- آدرس: `http://user:pass@<tcpHost>:<tcpPort>`
- در تلگرام دسکتاپ: Settings → Advanced → Connection type → **HTTP Proxy**.
- برای **تلگرام وب** و مرورگر: همان آدرس را در تنظیمات پروکسی سیستم یا افزونهٔ مرورگر بگذارید؛ چون TLS سایت تلگرام سرتاسری است، ترافیک رمزنگاری‌شده می‌ماند.
- مسیر در مالتی‌پلکسر: شروع درخواست با `CONNECT` یا متدهای `GET/POST/HEAD`.

```bash
curl -x http://user:pass@<tcpHost>:<tcpPort> https://api.telegram.org
```

## ۴) FakeTLS روی همان سکرت

بخشی از حالت MTProto است: سکرت `ee...` باعث می‌شود ترافیک از دید DPI شبیه TLS معمولی به دامنهٔ انتخابی باشد. تغییر دامنه، سکرت را باطل می‌کند؛ بعد از تغییر، «ساخت سکرت تازه» را بزنید.

## نکته‌های عملی

1. **یک پورت، چهار سرویس.** ترتیب تشخیص در مالتی‌پلکسر: TLS→SNI، سپس `0x05`، سپس متد HTTP، و در نهایت MTProto. اگر کلاینتی دارید که با بایت غیراستاندارد شروع می‌شود، به mtg می‌رود.
2. **ظرفیت پلن رایگان.** پروکسی MTProto برای ۳۰–۵۰ نفر هم‌زمان روی ۱ vCPU/۰٫۵ گیگ رم معمولاً کافی است، اما پهنای‌باند رایگان محدود است.
3. **امنیت.** سکرت MTProto را عمومی نکنید؛ برای هر گروه یک نصب جدا بسازید. SOCKS/HTTP هر دو رمز دارند و بدون رمز به‌طور پیش‌فرض بسته‌اند.
4. **قطعی تلگرام در ایران** هیچ ربطی به پنل ندارد؛ اگر پروکسی جواب نداد، اول پورت TCP و سپس وضعیت `mtg` در تب هسته‌ها را ببینید.
5. **گزارش زنده:** تب هسته‌ها → `mtproto` → خط‌های `mtg` شامل آمار اتصال و خطاهای شبکه است.
